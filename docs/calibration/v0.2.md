### 7.2 The cost split (v0.1.md §7's method)

**Method, as v0.1.** Each assistant message, merged by message id, is priced at its own usage. The basis is input
plus cache tokens at the model's list price, with output and thinking left unattributed. Each message is classed by
the tools it called, with priority recording > orientation > work:

- **orientation:** `directives list`, `memory search/list/show`, reads of `.wingfoil/directives/` or `docs/memory/`;
- **recording:** `memory add/submit/approve`, writes to `docs/memory/`;
- **work:** everything else; **exploration** is the work messages before the first change to `src/` in each step;
- **round trips:** every message of a step after its first session, i.e. after the approver's reply.

The alternative spreads the unattributed remainder (the run's reported cost minus the attributed part) over the
messages by the size of their visible text and tool input. The step costs are `run.json`'s.

### 7.3 S3, D5: the cancellation policy

Step 1's prompt states rule 5 ("a booking cancelled less than 24 hours before its start gets no refund; otherwise the

  decision-log: "its policy (no refund under 24h before start, otherwise full refund) is left for a later task". It
  then submitted the task. **Status at the end of step 1: pending** (submitted, never approved).
- **M, reference, step 5:** the agent ran `memory search --type decision-log --status approved`, which found nothing,
  and `memory search --type decision-log`, which listed `dl-001`…`dl-004`. It read `dl-004`. **It never opened

  before the start and none after, and recorded that as an assumption "to confirm with the school".
- **M, bridge (v0.2.2), step 1:** the agent kept only "Cancellation (rule 5) is not implemented yet, as requested",
  without the rule's content, in `dl-001` and in its message. In step 5: "The request gave no refund rule", the same

### 7.7 The five most important points

1. **WingFoil reaches the agent only through the CLI, and its process never makes a record approved.** Every step runs
   `directives list` and `memory search --status approved`, and none calls MCP or a workflow verb. The approved search
   finds nothing in almost every step, because the agent only submits its records. From step 2 or 3 the agent works
   around this with an unfiltered search. **(M)**
2. **S3's D5 failed in wingfoil for a process reason, not a model one.** The policy given in step 1 went nowhere
   (v0.2.2) or into a pending task (v0.3.0), and step 5's lookup searched decision-logs only: "The request does not
   state the refund rule." Baseline-docs wrote it in the README, which every step reads first. **(M, the cause I)**
3. **The D3 and S2-duplicate differences are wording, not behaviour.**
   - D3: v0.2.2 passed on "unchanged" containing "changed"; v0.3.0 recorded the new rule positively and failed.
   - S2: v0.3.0 looked `task-001` up and said the defect was "already" handled, but in words the check does not list.
   The preliminary bug finding on S3's M-F1 should not be filed as a WingFoil regression without this. **(M, I)**
4. **The process costs about the same share as in v0.1** (Sonnet 5.5, the alternative attribution): orientation
   18–26 %, recording 16–34 %. Round trips have almost vanished (0–1 % on Sonnet). On S1 the process adds about 9
   orientation and 11 recording messages a run (42 turns against 24). Its reads inflate every later turn's context by
   about 56 % per work message: cache reads 1.0 M against 0.42 M. **(M)**
5. **Interventions mostly confirm work already done.** 6 of 8 round trips only ran `memory approve`, for a few seconds
   and cents. 2 carried the work, because the agent stopped first. One was a false second approval request detected
   by the runner (Opus S1, step 2). **(M)**

**Limits.**
- n = 1 per scenario, except S1 on Sonnet.
- Messages are classed by regex over their tool inputs, with priority recording > orientation > work. A message that
  does both is counted once.
- Thinking is redacted in the stream and is part of the unattributed cost.
- Exploration cannot be separated from orientation on Sonnet 5.5 (§7.2).

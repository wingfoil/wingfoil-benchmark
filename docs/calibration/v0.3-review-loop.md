## 1. What was run

The approver gave the go in chat on 2026-11-17, with a ceiling of 168 EUR (eight dry runs at a 21 EUR worst case
each: the run's 3 EUR cap plus the loop's 18 EUR). The runs were S1, S2, S3 and S8 at 1.1, in `baseline` and
`wingfoil`, on `claude-sonnet-5-5`, one dry run each, numbered `dry-runs/208` to `215`.

The profile was `campaigns/v0-3-review-loop.dry-run.yaml` (task-152):

- **Pins:** v0.3's measured pins, frozen by the approver's choice of 2026-11-16: WingFoil v0.3.1, Claude Code
  2.1.300 at medium, approver policy v5, the run's cap 3 EUR.
- **Review loop:** task-151's. The reviewer is Claude Code 2.1.300 on `claude-sonnet-5-5` at medium, with
  `review/prompt.md` and `review/fixer-prompt.md`, and `max_rounds` 5.

Every figure is n = 1 per key, so it is preliminary. It says what the loop does and costs, not which arm is better.

## 3. What it cost

The sums come from the runs' records (each step's `costEur` and `review/loop.json`'s `cost_eur`), by a scratchpad
script:

- **Total:** 3.54 EUR, 2.1% of the 168 EUR ceiling. The steps cost 2.97 EUR and the loops 0.57 EUR (16.1% of the
  total).
- **Loop against steps, per dry run:** from 9.9% (S1 `wingfoil`) to 32.4% (S2 `baseline`).
- **Worst case against measure:** the estimate's worst case for a loop is 18 EUR, (2 × 5 − 1) sessions at 2 EUR each.
  The measured loops cost 0.03 to 0.18 EUR, so the worst case is 100 to 550 times the measure. A campaign estimate
  now prices each key's loop from these dry runs (task-151), not from that bound.

## 4. Reading

- **Seven of eight loops closed clean at round 1.** In each, one reviewer session read the diff and found nothing to
  report, and no fixer ran. On these four scenarios a Sonnet run mostly leaves nothing that this reviewer flags.
- **S3 `wingfoil` (`dry-runs/213`) ran the whole loop:**
  - **Round 1:** the reviewer flagged the plan elements 1-2 to 1-5 as WingFoil scaffolds left empty (should-fix), and
    a scaffold comment left in three tasks (nit). The fixer fixed both.
  - **Round 2:** the reviewer flagged a `parent` naming a plan that does not exist (should-fix), and plan bodies that
    only restate their task (nit). The fixer ran again.
  - **The end:** its change touched nothing the reviewer reads, so the loop ended `no fix`, as REQ-RUN-21 provides,
    not at `max_rounds`. M-V2 is 2/2.

  The findings are about the harness's own records, the elements the arm's workflow asks the agent to keep. The
  baseline arm keeps none, so it gives the reviewer less to flag.
- **The loop's cost scales with the rounds, not with the run.** A clean loop is one reviewer session (0.03 to
  0.07 EUR). The one loop with fixes cost 0.18 EUR: two reviewers and two fixers.

## 5. What the dry runs found

- **[bug-051](../memory/bug/bug-051-the-results-reader-refuses-a-fixer-round-s-usage-because-the-runner-records-its-interventions-as-a-list.md):**
  the runner wrote a fixer round's interventions as a list, and the results reader required a number. `dry-runs/213`
  could not be read back, so the figures script stopped, the estimate skipped it, and the aggregate would have
  failed.
- **Fix:** task-153 reads the list and tests the runner's own writer against the reader. No stored record was
  rewritten and no dry run was repeated.

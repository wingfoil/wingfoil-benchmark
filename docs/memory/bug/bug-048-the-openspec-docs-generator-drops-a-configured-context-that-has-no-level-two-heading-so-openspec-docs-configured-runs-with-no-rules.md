## Context

Found by [task-144](../task/task-144-w18-every-arm-s-dry-run-on-s1-s2-s3-and-s8-at-1.1-the-configured-arms-included.md)
while reading its stage 1 (S2@1.1 in the six configured arms, 2026-11-09). A configured docs control is generated by
its harness's generator from the configured arm's configuration as captured after setup (REQ-RUN-11 as amended in
1.50). The openspec-docs generator, `renderOpenSpecDocs` in `src/arms/docs-controls.ts` (task-072), keeps the
`context` of `openspec/config.yaml` only from its first line starting with `## `: the shape the openspec arm's rules
generator writes (REQ-FMT-14, task-071). The configuring agent wrote each of the four openspec configurations
(S1, S2, S3, S8 at 1.1, task-143) as a context of plain paragraphs and lists, with no `## ` line.

## Expected

`openspec-docs-configured` gets, as `PROJECT_RULES.md`, the context the configuration holds, as
`speckit-docs-configured` gets the configured constitution and `baseline-docs-configured` the configured directives.

## Actual

`dry-runs/160` (S2@1.1, openspec-docs-configured, completed, 0.1891 EUR) got the generator's "no rules" text,
"This project declares no rules beyond its README.", and none of the 28 lines of 40 characters or more of
`scenarios/S2/1.1/arms/openspec-configured/openspec/config.yaml` (counted by a scratchpad script over the dry run's
`setup/diff.patch`). In the same count, `dry-runs/158` (speckit-docs-configured) holds 50 of 50 lines of its
constitution and `dry-runs/156` (baseline-docs-configured) 4 of 4 of its directive. None of the four openspec
configurations has a `## ` line, so the control would run without its configuration on every version; it is no
control of `openspec-configured`. The configurations themselves are right, and `openspec-configured` reads them
(`dry-runs/159`).

## Fix (proposed, for the approver's choice)

1. **Recommended:** a context with no `## ` line is rendered whole under `## Rules`, rather than as "no rules"; a
   context with one keeps today's rendering, so the non-configured openspec-docs control and its digest-pinned runs
   are unchanged. A red test with S2's configuration first. Inside task-144, then `openspec-docs-configured`'s four
   dry runs (S2 again, S1, S3, S8) after the fix; `dry-runs/160` stays as recorded, a note in the reading.
2. Or a task of its own after task-144, which runs the other 48 dry runs now and these four later.

No configuration changes either way (REQ-FMT-04): the defect is the generator's.

# WingFoil Benchmark v0.2 — Competitors

**Date:** 2026-10-22
**Release element:** [rel-v0-2](../memory/release/rel-v0-2.md) · **Plan:** [plan-004](../plans/plan-004-release-v0-2.md)

v0.2 adds two competitor harnesses, **Spec Kit** and **OpenSpec**, each with a docs control. It moves to the Claude
5.5 models and to **WingFoil v0.3.0**, and it re-runs v0.1's configuration on the new model as a **bridge**, so that
v0.1 and v0.2 can be compared one change at a time. Its results are **preliminary**: only S1 ran three times per
arm, and no claim of statistical significance is made.

  `harnesses.tar.gz`, assets of the releases

## What is compared

The same agent and model work through the same tasks in seven arms. Only the harness around the agent changes:

- **baseline**: the agent, the starting project and a short operating manual;
- **wingfoil**: WingFoil **v0.3.0** (`cc31d7a8`), set up as its documentation says, with its MCP server;
- **speckit**: GitHub's Spec Kit **v1.1.0**, through its skills;
- **openspec**: OpenSpec **1.14.0**, through its commands, propose, apply and archive;
- **baseline-docs**, **speckit-docs**, **openspec-docs**: each harness's docs control, which gives the same
  information as one plain Markdown file without the tool. It is a control for "more context, not the harness".

Every harness is admitted by the published eligibility criteria, and WingFoil is assessed like the others. BMAD
(6.12.1) was assessed and excluded: its process is not documented as runnable without a person supplying the
project's content to its facilitations. That reading of its documentation is open to contest.

**Pins:** Claude Code 2.1.300, model `claude-sonnet-5-5` at effort `medium`, approver policy v1. Costs are
API-equivalent, at 0.8917 EUR/USD, whatever the actual billing: the agent ran on a subscription.

## Results, in short

On Sonnet 5.5, one pass of S1–S8 (S1 is the mean of three runs):

| | Hidden tests | Hold-out | Checks | S3 continuity (M-F1) | Cost of the pass | Against the baseline |
|---|---|---|---|---|---|---|
| baseline | 246.7/249 | 87.0/89 | 14/20 | 3/5 | 1.17 USD | 1.00× |
| baseline-docs | 246.0 | 85.3 | 18/20 | 4/5 | 1.53 | 1.32× |
| wingfoil (v0.3.0) | 246.0 | 85.0 | 18/20 | 3/5 | 1.90 | 1.63× |
| speckit | 241.3 | 85.0 | 19/20 | 3/5 | 2.07 | 1.77× |
| speckit-docs | 246.7 | 87.0 | 18/20 | 3/5 | 1.15 | 0.98× |
| openspec | 248.3 | 86.0 | 20/20 | 5/5 | 3.21 | 2.75× |
| openspec-docs | 246.0 | 85.0 | 18/20 | 3/5 | 1.15 | 0.98× |

How to read it:

- **Correctness is nearly the same in every arm.** These scenarios give one request per session, and Sonnet 5.5 passes
  almost every hidden test without any harness. The arms differ on the **checks** (S2's recall across sessions, S3's
  revision on record, S8's rules): the baseline keeps 14 of 20, every other arm 18 or more.
- **Written rules alone give most of that gain.** Each docs control reaches 18/20 at about the baseline's cost.
- **OpenSpec** is the only arm with every check and every S3 decision kept, at 2.75 times the baseline's cost.
- **WingFoil v0.3.0** matches its docs control on correctness and checks, at 1.63 times the baseline. Against v0.2.2,
  in the bridge, its cost relative to the baseline falls on every scenario (S2 from 1.90× to 1.22×), and on S3 it lost
  a decision revision that v0.2.2 recorded (one run each).
- **Spec Kit** costs 1.77 times the baseline and lost five hidden tests on S3 (one run).

**The models** (S1, one run each on Opus 5.5 and Haiku 5.5):

- **Opus 5.5** passes every hidden and hold-out test in its three arms, at 4–5 times Sonnet's cost.
- **Haiku 5.5** with WingFoil passes every test of S1 (165/165, 48/48) for 0.15 USD, against Haiku without a harness at
  164/165, 45/48. On S3 the same arm falls to 30/37 against the baseline's 35/37. The weak-model hypothesis is
  therefore mixed.

**From v0.1 to v0.2** (`c82a5e74885b/2` → the bridge → the reference campaign):

- **The model, the agent and the effort** (the first step, WingFoil held at v0.2.2): S1's cost per run fell from
  3.82 € to 0.60 € in the wingfoil arm, and from 2.22 € to 0.42 € in baseline-docs. Correctness stayed within the
  runs' spread.
- **WingFoil v0.2.2 → v0.3.0** (the second step, alone): see above.

## The hypotheses written before v0.2

v0.1's calibration stated what WingFoil's next version was expected to change. [Calibration v0.2](../calibration/v0.2.md)
§9 restated them on Sonnet 5.5, and the campaigns tested them:

- **Hold:** H2 (fewer turns on S1), H5 (S8's rules and hidden tests), H6 (no loss of correctness), H7.
- **Hold in part:** H1. WingFoil's cost relative to the baseline falls on all four scenarios, but S1 stays at 1.70×,
  above the 1.5× the hypothesis set.
- **Fail:** H3 (S3's continuity), H4 (S2's recall, 2 of 3), H8 (WingFoil within 1.1× of its docs control: 1.23×) and
  H10 (the new models do not saturate the checks).
- **Not measurable:** H9, since all scenarios are one request per session.
- **Mixed:** H11, the weak model.

WingFoil v0.3.0 declares a workflow engine, but its scaffold declares no workflow and no scenario's request starts
one. The engine's own hypotheses therefore read WingFoil as its documentation sets it up. A scenario that needs gates
and roles is left to a later release.

## Known limits

- **Preliminary:** S2, S3 and S8 ran once per arm, and so did both model slices. Only S1 has three runs, and S1's
  last step varies from run to run (158 to 165 of 165 in the same arm). No difference is claimed as significant.
- **Saturation:** on these scenarios Sonnet 5.5 is near the ceiling in every arm. The harnesses differ on cost and
  checks more than on correctness.
- **The comparison with v0.1** changes the model, Claude Code, the effort, the manual and the scoring code together
  in its first step. Only the bridge's second step isolates WingFoil.
- **OpenSpec's arm** tells the agent to carry each request through propose, apply and archive in one session. As
  installed, OpenSpec's propose step waits for a new request that a headless session never gets (bug-023).
- **Benchmark by WingFoil's maintainer** (threat T1): the questions, metrics and hypotheses were fixed before any
  run, and losses are published like wins.

## Changes in the benchmark since v0.1

- the competitor arms and their docs controls, generated from each tool's own configuration;
- each arm pinned by a digest, and an arm read from history when a campaign pins an older one, which is how the bridge
  runs v0.2.2 beside v0.3.0;
- the effort pinned per model, the observed models recorded per step, and Sonnet 5.5's cache reads priced right;
- the comparison of two executions, with what changed between them, on the site;
- a campaign can be stopped, resumed, and stopped early on repeated errors;
- an eligibility register for every harness and version.
